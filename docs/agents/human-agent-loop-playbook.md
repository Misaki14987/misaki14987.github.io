# Human–Agent Loop 工程实践手册

## 1. 这套方法解决什么问题

复杂的设计与工程任务很少能靠一条提示词完成。一次长任务可以实现功能，却不一定同时解决方向、视觉、动画、可靠性和审美判断。

这里的 **Loop** 不是让 Agent 无限修改，而是一个有边界的验证闭环：

```text
明确本轮问题
→ 建立可复现基线
→ 收集证据
→ 选择影响最大的问题
→ 做最小修正
→ 重新验证
→ 达到停止条件
→ 交还给人判断下一轮方向
```

一轮只回答一种问题。方向、质感、动画和发布验收如果混在一起，Agent 很容易用更多效果掩盖基础问题，也难以证明哪次修改真正有效。

## 2. 基本原则

### 2.1 Loop 必须有限

每轮开始前必须写清楚：

- **Goal**：本轮只改善什么；
- **Context**：代码、领域文档、真实内容和已有决定；
- **Constraints**：什么不能改；
- **Evidence**：用什么截图、录屏、测量或测试判断；
- **Done when**：什么结果允许停止；
- **Escalation**：什么情况必须交给人决定。

缺少停止条件的“继续优化到足够好”不是 Loop，而是无限润色。

### 2.2 一轮只处理一个质量维度

推荐顺序是先解决高层不确定性，再解决低层细节：

```text
方向 → 视觉基础 → 叙事与动画 → 证据预检 → 发布验收 → 人眼评审 → 定点修复
```

上游决定尚未稳定时，不要打磨下游。例如布局方向未确定前，不值得精修某个按钮的动画。

### 2.3 证据先于修改

问题必须能由至少一种证据支持：

- 截图或前后对比；
- 完整交互录屏；
- DOM、尺寸、溢出和计算样式测量；
- 控制台、网络和性能数据；
- 自动测试或可重复操作步骤；
- 人明确指出的主观体验。

“感觉还不够高级”和“这是设计选择”都不是证据。

### 2.4 每次修影响最大的一类问题

Agent 先按影响排序，再只修最高优先级的一类。修完立即复测，不顺手重构附近代码，不为未来主题搭框架，不新增与本轮无关的功能。

### 2.5 自动化证明没有坏，人判断是否值得

程序可以证明页面没有溢出、导航正确、控制台干净；它不能证明页面有情绪、像作者本人或令人难忘。

因此 Agent 可以自主完成一轮内部迭代，但轮与轮之间的审美和产品方向应由人确认。

## 3. 人与 Agent 的职责边界

| 工作 | 人 | Agent |
| --- | --- | --- |
| 定义目的、受众和个人品味 | 决策 | 提问、整理 |
| 读取代码、追踪真实流程 | 提供入口 | 负责 |
| 拆分本轮范围与验收标准 | 确认关键约束 | 起草并执行 |
| 普通视觉和实现细节 | 无需逐项审批 | 自主决策 |
| 构建、截图、测量、测试 | 抽查 | 负责 |
| 主观审美与情绪判断 | 负责 | 提供候选和证据 |
| 删除内容、发布、付费、扩大需求 | 必须授权 | 停止并请求授权 |
| 决定是否开启下一轮 | 负责 | 给出建议，不自行无限续跑 |

人不需要参与每次代码修改。通常只在以下节点介入：

1. 开始前确认目标和不可改变项；
2. 方向候选中选择或确认一个方向；
3. 一轮完成后实际浏览并指出最重要的感受；
4. 发布、推送、删除数据或扩大范围前授权。

## 4. Agent 如何拆解并运行一轮 Loop

### 4.1 读取约束和真实流程

开始修改前：

1. 读取 `AGENTS.md`、领域词汇、相关工作流和决定记录；
2. 检查工作树，区分已有用户改动与本轮范围；
3. 追踪入口、状态、导航、内容和测试的真实调用链；
4. 运行现有构建和最小相关测试，建立基线。

不要跳过理解阶段去追求小 diff；改错位置会制造第二个问题。

### 4.2 建立问题清单

问题按以下等级排序：

- **BLOCKER**：核心功能不可用、内容丢失、安全边界失效；
- **HIGH**：明显视觉破损、主题泄漏、移动端不可读、导航错误；
- **MEDIUM**：可感知且有明确收益，但不阻碍完成任务；
- **LOW**：主观润色、几乎不可见或没有证据的问题。

设计 Loop 可以使用该排序，也可以按“最破坏目标体验的五个问题”排序，但不能一次全修。

### 4.3 选择最小修正

优先顺序：

1. 删除不需要存在的代码；
2. 复用仓库现有模式；
3. 使用 CSS、HTML、浏览器 API 和标准库；
4. 使用已经安装的依赖；
5. 最后才增加最小的新实现。

修复应落在所有相关路径共享的根因位置。不要只给报告中的单个页面打补丁，而让同类页面继续出错。

### 4.4 复测并决定是否继续

每次修正后只跑最小相关检查。阶段结束时再运行完整门禁。

继续下一次内部迭代，需要同时满足：

- 仍有符合本轮目标的 BLOCKER、HIGH 或有明确收益的 MEDIUM；
- 问题有可观察证据；
- 修改不扩大本轮范围。

如果连续一次只发现 LOW、误报或主观差异，立即停止该 Loop。

### 4.5 输出交接

每轮报告至少包含：

- 本轮结论；
- 修改了什么以及证据；
- 构建和测试结果；
- 未修改的 `DEFER` 及其触发条件；
- 需要人判断的唯一下一步；
- 是否涉及发布、提交或其他待授权操作。

不要用“Awwwards 水平”“生产级”代替具体证据。

## 5. 推荐的 Loop 序列

并非每个项目都需要全部 Loop。只运行当前存在真实问题的那一轮。

### Loop 0：基线与 Checkpoint

**目的**：确认当前状态可构建、可回退，并避免把旧问题归因于新修改。

Agent 执行：

- 检查工作树和相关历史；
- 运行构建与已有测试；
- 记录目标视口和关键路径；
- 在用户授权后创建 checkpoint commit。

停止条件：基线结果明确，工作范围清楚，已有改动得到保留。

### Loop 1：方向探索

**目的**：在高成本实施前回答“应该做哪一种”。

Agent 执行：

- 用同一份真实内容制作少量明显不同的候选；
- 使用同一组加权标准比较；
- 截取桌面、移动端和关键状态；
- 记录胜出原因及被拒方向，不永久保留多个试验分支。

人执行：确认胜出方向是否符合个人品味和网站身份。

停止条件：只有一个生产方向，选择理由和舍弃内容已经记录。

### Loop 2：视觉质感与排版

**目的**：消除占位感，建立可靠的字体、层级、材质和响应式构图。

本轮只处理：

- 素材可信度；
- 字体和中英文混排；
- 颜色、层级、留白和纸张质感；
- 风格泄漏、文字裁切和移动端拥挤。

不处理：新增场景、复杂动画、通用设计框架。

停止条件：目标视口没有明显占位素材、裁切、风格泄漏或构图破损。

### Loop 3：滚动叙事与动画

**目的**：把独立效果连接成有起点、发展和结束的阅读过程。

Agent 执行：

- 录制慢速、快速和反向滚动；
- 找出最明显的一处叙事断裂；
- 每个场景只保留一个主要物理事件；
- 检查快速滚动、反向滚动和 reduced-motion；
- 优先使用 CSS、Web Animations API、`IntersectionObserver` 和 `requestAnimationFrame`。

拒绝：重复 fade-up、滚动劫持、无原因视差、为了独特而给每个元素加动画。

停止条件：相邻场景没有明显跳变、空白死区或错误残留，动画不妨碍阅读和操作。

### Loop 4：Preflight CheckLoop

**目的**：在继续修改前，验证“已知限制”和交接摘要是否真的成立。

这是只读 Loop：先不改代码，只尝试推翻现有声明。

每项声明输出：

| 声明 | 证据 | 实际影响 | 判定 |
| --- | --- | --- | --- |
| 待验证说法 | 截图、录屏、测量或代码位置 | 用户是否真的受影响 | PASS / FIX / DEFER |

- **PASS**：多个目标环境下没有实际问题；
- **FIX**：已观察到理解、导航、失效或视觉问题；
- **DEFER**：问题存在但不影响当前发布，并写明未来触发条件。

停止条件：所有声明都有证据和判定。只有 `FIX` 进入后续修复。

### Loop 5：发布验收

**目的**：证明当前版本可以发布，不再探索新设计。

覆盖：

- 视觉完成度和主题边界；
- 目标视口和真实长内容；
- 首页、文章、日记、刷新、前进/后退与锚点；
- 键盘、焦点、reduced-motion 和语义；
- 控制台、网络、布局稳定性和已有测试。

只修 BLOCKER、HIGH 和有明确发布收益的 MEDIUM；LOW 记录后停止。不得新增功能、素材、动画或架构。

停止条件：发布门禁通过，或者存在明确阻塞并交给人决策。

### Loop 6：人眼审美评审

**目的**：判断“没有坏”之外，它是否真的有吸引力、像作者本人。

这一步由人在真实浏览器和至少一台真实手机上完成。只回答：

1. 第一眼是否想继续阅读？
2. 最喜欢哪一幕，为什么？
3. 哪一幕显得廉价、重复、突兀或令人困惑？
4. 如果下一轮只能改一件事，应该是什么？

反馈必须包含具体视口、位置、操作和感受。例如：

> 390px 首页，从 Diary 滚到 About 时连续出现两次翻面，第二次让我感觉是在重复模板。

停止条件：人接受当前版本，或产出一个具体、可复现的下一轮问题。

### Loop 7：定点修复

**目的**：只解决人眼评审或真实用户反馈中的一个具体问题。

Agent 先复现、解释根因，再做最小修改；不得顺带重做其他场景。完成后检查受影响的桌面、移动端、reduced-motion 和最小相关测试。

停止条件：该问题有前后证据且不再复现。新的无关发现进入待办，不扩大当前 Loop。

### Loop 8：真实反馈

**目的**：让实际访问行为决定是否需要下一轮，而不是 Agent 自我驱动地继续润色。

可收集：读者是否理解主题切换、是否能找到文章、在哪一段离开、是否报告设备问题。只有重复出现或影响目标的反馈才开启新 Loop。

## 6. 验证矩阵

不同证据回答不同问题，不要互相替代：

| 证据 | 能证明 | 不能证明 |
| --- | --- | --- |
| 构建和自动测试 | 代码可编译、已编码行为没有回归 | 页面好看 |
| DOM 和尺寸测量 | 溢出、裁切、位置、可见性 | 构图有情绪 |
| 截图 | 单个状态的视觉层级 | 动画节奏和操作连续性 |
| 录屏 | 场景衔接、节奏、快速/反向滚动 | 真实触控手感 |
| 真机检查 | 字体渲染、触摸、性能和系统差异 | 所有设备都正确 |
| 人眼评审 | 品味、身份、记忆点和价值 | 导航逻辑全覆盖 |

如果执行环境无法查看图片，Agent 必须明确说明只能完成程序化验收，不能据此宣称主观视觉目标已经达成。

## 7. DEFER 的写法

`DEFER` 不是“以后再说”，必须包含：

```text
现象：什么确实存在
当前影响：为什么不阻塞
触发条件：发生什么才值得修
最小修法：触发后优先尝试什么
```

没有触发条件的限制会永久留在报告里；没有实际影响的问题则不该进入待办。

## 8. 常见失败模式

- **一条提示词包办所有阶段**：无法分辨修改收益；拆成单目标 Loop。
- **无限“再高级一点”**：没有证据和停止条件；交给人眼评审。
- **Agent 自己证明自己正确**：同一实现与同一指标形成闭环偏差；引入人或真实用户。
- **把限制写成辩护**：例如“这是设计选择”；用交互和视觉证据验证。
- **只测 happy path**：补充刷新、历史、失败请求、快速/反向操作和 reduced-motion。
- **用自动化替代审美**：指标通过只代表没有明显损坏。
- **为了第二个主题先建框架**：等真实重复出现，再提取共享边界。
- **修 LOW 时引入 HIGH 风险**：发布验收只处理明确影响发布的问题。
- **永久保留原型**：记录决定后吸收胜出方案，删除输掉的实验代码。

## 9. 可复用提示词骨架

```text
创建一个持久目标：<本轮唯一目标>。

开始前：
- 阅读 AGENTS.md、领域文档和相关工作流；
- 检查 git diff，保留已有用户改动；
- 运行现有构建和最小相关测试建立基线。

本轮只处理：
- <范围 1>
- <范围 2>

不得处理：
- <明确排除项>
- 不新增无关依赖、框架、功能或抽象。

循环：
1. 用 <截图/录屏/测量/测试> 收集证据；
2. 按影响排序问题；
3. 每次只修影响最大的一类；
4. 做最小相关复测；
5. 仍有符合本轮范围的高价值问题时继续；
6. 连续一次只剩 LOW、误报或主观差异时停止。

完成条件：
- <可观察条件>
- <目标环境>
- <必须通过的命令>

必须保留：
- <现有能力和内容>

需要人确认：
- 删除内容、外部发布、付费、扩大需求或改变产品方向。

完成后输出：
- 结论和证据；
- 修改与验证结果；
- DEFER 及触发条件；
- 需要人的唯一下一步。
```

## 10. 本项目的推荐命令与证据

Newspaper 主题的专用约束仍以 `newspaper-theme-workflow.md` 为准。当前最小完整门禁是：

```bash
pnpm build
pnpm test:theme -- http://127.0.0.1:<port>
```

目标视口：

- 1440×1200；
- 1000×1600；
- 390×844；
- 360×800。

长期决定写入 `newspaper-theme-verdict.md`，临时截图和测量放入已忽略的本地证据目录，不提交大量生成物。

## 11. 最终准则

好的 Human–Agent Loop 不是让人退出工程过程，而是重新分配注意力：

- Agent 承担重复、可测量、可验证的执行；
- 人把精力留给目标、品味、价值、风险和是否继续；
- 每一轮都有证据、有边界、有停止条件；
- 没有具体问题时，停止修改并让真实使用产生下一条证据。
